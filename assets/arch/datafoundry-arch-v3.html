DataFoundry:harness 装技能,技能带登录

训练数据的品控与归因层——让每一条数据的去留都有可辩护的理由。用户不"访问产品": 在自己的智能体工作台里装上四个技能文件,剧本就会驱动一切,包括注册与登录。 原生的是认知(租),确定的是裁决与账本(自有)。

主链:意图 →(AI)配方提案 →(人)授权 →(系统)精炼事实 —— AI 只进前两段,这条线就是安全线

技能包 = 产品入口(论旨) 人手环节:授权只属于人 虚线 = 可选 / 只建议

整体机制:机器流水平走,授权由人从上方插入

从左到右是一次精炼的完整机器路径;两个琥珀色节点是仅有的人手环节——批准登录、扫码付款。其余一切可由智能体按剧本完成。

代码三域 = 目录 = 发行边界tests/test_domains 守护

物理目录即架构,归类是设计动作:新模块不入域册,测试响亮失败。

kernel/ 精炼内核

schema · 算子(依赖契约)· 漏斗编译器 · 执行器 · 配方 · 证据包。纯标准库零第三方依赖—— 树莓派、离线机、私有化今天即可跑。pip install datafoundry

service/ 服务壳

API · RBAC · 计费(PG 账本)· 限流 · 审计 · 只读控制台。 pip install datafoundry[server],禁引 interface。

interface/ 薄客户端

CLI(本地离线流)与 MCP 适配器(可选)。只经 HTTP 窄腰访问服务,永不 import 服务内部。

五律(什么永远不变)

  • I1每条处置必有可追溯死因(trace append-only)
  • I2裁决确定性:同输入+同配方+同平台版本 → 同输出;AI 只建议
  • I3资金唯一写入点、同事务、幂等;失败退款双向留痕
  • I4对外数字必可复现(seed+sha256+run id),不可复现不外发
  • I5认知可替换:任何 agent / 模型都是可插拔外设

安全线(四条"永不")

四条窄腰(样本 schema · 算子协议 · 事实文件族 · REST 认知接入面)之外,一切实现可翻新。红线:

判审永不单独杀样本 AI 永不动账本/放行交付 支付授权永不进智能体 Mission 只花人预授预算
