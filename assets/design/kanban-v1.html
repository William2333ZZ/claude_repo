裁定

四条不变量与一张白名单

看板是投影

不产生新事实,只呈现已裁决的事实(I1/I4 的展示面)。

写 = 人手白名单

白名单外绝不长写路径;入口与 REST 共用同一 service 函数。

看板不是心脏

技能 / REST / kernel 对看板零依赖,看板宕机平台照常干活。

零构建链 SSR

FastAPI + Jinja2,签名 cookie 会话 + 全 CSRF;node/webpack 不进仓。

写动作白名单(全部是人手环节):注册登录(密码人打,永不经 agent)· 设备码批准 · 建单 + 扫码支付(支付授权永远人手)· 下载交付 · 分享链生成 / 吊销 · API key 吊销 · 样例尸检(零扣费限流)。
明确不进 v1(登记触发,不是遗漏):浏览器上传 / 配管线 / 跑管线——「做」的活留给技能面; 触发 = 无-harness 访客占比可观。邮箱找回、SPA 同理,各有触发条件(docs/28 §3-4)。

五个阶段,每段独立可验收(#30)

30-B我的看板

总览 / Run 详情 / 数据集 / 配方档案。验收:死因与 REST 逐条一致。

30-C账务与授权

流水 · 建单 → 去支付 · 到账自刷 · 设备码页收编。验收:扫码到账余额跳变。

30-D公开区

Landing 铁证橱窗 + 定价 + 装技能 + 样例尸检。验收:无账户 3 分钟见裁决。
