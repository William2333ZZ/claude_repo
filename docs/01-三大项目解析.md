# 01 · 三大项目深度解析（事实层）

> 本文是产品思考的事实基础：三个项目 2026 年年中的真实架构、能力边界与短板。
> 所有数字与组件名均来自官方文档、GitHub 仓库与论文，尾注列来源。

## 1. NVIDIA NeMo：从单体框架到 28 个仓库的生态

### 1.1 现状架构

NeMo 已经不是一个仓库。2025 年 NVIDIA 把 `NVIDIA/NeMo` 单体仓库拆成了 **NVIDIA-NeMo GitHub 组织（约 28 个仓库）**：

- **NeMo Framework 2.0**：抛弃 1.0 的 YAML/Hydra，改为 **Python 优先配置（Fiddle）**；训练建立在 **Megatron-Core**（张量/流水线/上下文并行）+ **Transformer Engine**（FP8）之上，按月发布 NGC 容器（如 25.11）。
- **Megatron-Bridge**：PyTorch 原生训练循环，`AutoBridge` 双向在线转换 HF ↔ Megatron 检查点，30+ 模型家族，LoRA/DoRA——实质上是 NeMo 2.0 LLM 路线的继任者。
- **Automodel**：DTensor/SPMD 原生、FSDP2，HF Transformers 模型（含 MoE、VLM）day-0 微调，LoRA/QLoRA、蒸馏。
- **NeMo RL**：**NeMo-Aligner 已于 2025-05 归档弃用**，继任者 NeMo RL 用 **Ray 编排**、vLLM 或 Megatron 生成后端，支持 SFT、DPO、RM、PPO、**GRPO、DAPO**、on-policy 蒸馏（Nemotron-3-Nano 用它训练）。**NeMo Gym** 提供 OpenAI 兼容 schema 的 RL 环境。
- **NeMo-Run**：实验配置/启动/管理，支持本地、Docker、**Slurm、Kubernetes** 执行器。
- **其他**：Guardrails（Colang DSL 护栏）、Evaluator（学术基准 + LLM-as-judge）、Export-Deploy（TensorRT-LLM/vLLM 导出）、DataDesigner（合成数据，源自收购的 Gretel）。
- **NeMo 微服务平台（2025-04 GA，闭源）**：Customizer（微调即服务）、Evaluator、Data Store（暴露 HF Hub 兼容 API 的文件存储）、Entity Store、NeMo Retriever（抽取/嵌入/重排 NIM）。

### 1.2 NeMo Curator（数据侧，与本产品最相关）

仓库 `NVIDIA-NeMo/Curator`，**Apache-2.0**。GPU 加速数据整备，覆盖四个模态：

- **文本**：去重、~30+ 启发式质量过滤、语言识别、质量/领域分类器、PII 脱敏
- **图像**：美学/NSFW 过滤、嵌入、去重
- **视频**：场景检测、切片抽取、运动过滤、去重
- **音频**：ASR 转写、WER 过滤

去重三件套：**精确（MD5）、模糊（MinHash+LSH）、语义（嵌入聚类）**，全部经 **RAPIDS（cuDF/cuML/cuGraph）** GPU 加速。关键架构变化：**已从 Dask 全面迁移到 Ray**，26.02 版本把所有模态统一到 Ray 流水线上，生产默认执行器为 **XennaExecutor（Cosmos-Xenna）**。格式支持 JSONL、Parquet、WebDataset。性能口径：模糊去重较 CPU 约 16x，H100 1–4 节点线性扩展；曾支撑 Nemotron-4 的 8T+ token 语料整备。

### 1.3 训练数据入口（整合的对接点）

| 阶段 | 期望格式 |
|---|---|
| 预训练 | JSONL → `preprocess_data_for_megatron.py` → 内存映射 **`.bin`/`.idx`**；`blend`/`blend_per_split` 按权重混合多语料 |
| SFT | `training/validation/test.jsonl`，**`"input"`/`"output"`** 键；可配 `prompt_template`、`answer_only_loss`、packed sequence；Automodel 可直接吃 HF datasets（任意列名映射） |
| RL（SFT/GRPO） | JSONL 或 HF datasets，**OpenAI `messages` 格式** |
| DPO | `PreferenceDataset`：`context`（消息列表）+ `completions`（带 rank，rank 0 为优选） |
| 微服务 | 数据集经 HF Hub 兼容 API 上传 Data Store，供 Customizer 消费 |

### 1.4 许可与开放性

开源仓库（NeMo、Curator、RL、Megatron-Bridge、Automodel、Run、Evaluator 库、Guardrails、Megatron-LM）均为 Apache-2.0。闭源层：NIM 容器、微服务控制面（Customizer/Data Store/Entity Store、Retriever NIM）——开发免费，生产需 **NVIDIA AI Enterprise** 订阅；部分模型是 NVIDIA Open Model License 而非 OSI 许可。

### 1.5 短板（第三方机会）

1. **硬件锁定**：GPU 路径 RAPIDS/CUDA-only，无 ROCm/TPU，CPU 回退在规模上不实用。
2. **API 变动剧烈**：1.0→2.0（Hydra→Fiddle）、单体→拆库、Curator Dask→Ray 重写——催生「稳定抽象层」的空间。
3. **没有数据质量归因闭环**：Curator 只管过滤，不做「数据切片 ↔ 下游评测增益」归因；无数据集血缘/版本管理（Data Store 只是文件存储）。
4. **无配方/实验管理生态**：NeMo-Run 只管发任务，追踪交给 W&B/MLflow，没有社区配方注册表。

## 2. Data-Juicer：数据处理的「规模层操作系统」

### 2.2 基本盘

阿里通义实验室开源，已从 `modelscope/data-juicer` 迁至独立 **`datajuicer` GitHub 组织**（旧地址重定向），同组织还有 `data-juicer-sandbox`、`data-juicer-agents`、`data-juicer-hub`（社区配方库）。自我定位从「一站式数据处理系统」升级为「**基础模型时代的数据操作系统**」。学术背书：系统论文 SIGMOD 2024，**Data-Juicer 2.0 为 NeurIPS 2025 Datasets & Benchmarks Spotlight（前 3.1%）**。版本注意：「2.0」是系统代际品牌，PyPI 包 `py-data-juicer` 实际版本 v1.5.5（2026-08），月度发版。

**算子库：230 个 OP、8 大类**——Mapper 138、Filter 58、Deduplicator 10、Formatter 8、Selector 6、Aggregator 4、Grouper 3、Pipeline 3（如 `llm_inference_with_ray_vllm_pipeline`）。算子带能力标签（CPU/GPU、vLLM、API、HF 模型、模态）。流水线是声明式 **YAML「配方」**：

```yaml
project_name: 'demo-process'
dataset_path: './demos/data/demo-dataset.jsonl'
np: 4
export_path: './outputs/demo-processed.jsonl'
process:
  - language_id_score_filter: {lang: 'zh', min_score: 0.8}
```

v1.5.5 起支持 **pip 安装的外部算子插件**——第三方扩展点已经打开。

### 2.2 多模态与领域配方

文本、图像、音频、视频均为一等公民（如 `video_motion_score_raft_filter`、`video_frames_text_similarity_filter`、`image_nsfw_filter`）。**DJ-SORA** 是构建 Sora 级视频训练数据的可复用配方套件；2026 年新增 **HumanVBench** 人本视频算子与**具身智能/VLA**（视觉-语言-动作）算子——多模态纵深是三者中最强的。

### 2.3 分布式（核心竞争力）

**Ray 深度集成**（在 Ray 官方文档中有专页；Anyscale 发布过用 DJ 做 FineWeb 去重的教程）。公开性能口径：

- **70B 样本、6,400 CPU 核、2 小时**处理完（25–100 节点阿里云集群）
- MinHash **RayDeduplicator：5TB 数据、1,280 核、2.8 小时**，靠负载均衡 BTS union-find 与哈希聚合比原生 Ray 快 2–3.3x
- 2026 年新增：分区 Ray 执行器、弹性多节点分片、分布式 RayAnalyzer、HDFS+S3 I/O

存储生态：Arrow、**Hudi、Iceberg、Paimon、Delta Lake、LanceDB**——湖仓对接已经现成。

### 2.4 Sandbox 与 Agent（闭环的原型）

**Sandbox**（ICML 2025 Spotlight，前 2.6%）是「**Probe–Analyze–Refine**」数据-模型协同开发循环：低成本探针实验 → 相关性/重要性分析 → 配方精化 → 编排处理+训练+评测任务。实证：EasyAnimate 借此**登顶 VBench 文生视频榜**，图文任务平均 +7.13%（TextVQA/MMBench/MME）。——这是「数据配方闭环能涨点」的最强公开证据，但它目前只在 DJ 自己的算子空间里转。

**data-juicer-agents**（基于 AgentScope）：DJ Process Agent、Dev Agent、**InteRecipe**（自然语言交互式配方构建）、DJ Copilot（2026-01 上线文档站/钉钉/Discord）。服务层：RESTful API + **MCP Server 两种模式**（recipe-flow：`search_ops`/`run_data_recipe`/`analyze_dataset` 等工具；granular-operators：每个算子一个 MCP 工具）。注意：agents 套件还很早期（~56 stars）。

### 2.5 生态位

Apache-2.0，~6.9k stars。生产使用：通义系产品（点金、智文、星辰）、深度集成**阿里云 PAI**；公开采用者含蚂蚁、字节、比亚迪、京东、**NVIDIA**、OPPO、小米、火山引擎。集成：HF datasets、ModelScope、LLaMA-Factory、**NVIDIA NeMo**、AgentScope、EasyAnimate、Ray。

### 2.6 短板

1. **语义深度是新补的、还薄**：230 个算子大盘子是统计/启发式（困惑度、比率、simhash/minhash）；LLM 算子（`llm_condition_filter`、语义抽取框架）2025–26 才落地，受 API/GPU 成本约束，落后于 FineWeb-Edu 式「训练出来的质量打分器」路线。
2. **合成广而不深**：有配图/增广/QA 生成类 mapper，但都是单次模型调用的包装，没有 distilabel 式多阶段合成 DSL。
3. **训练侧只有外循环**：Sandbox 靠离线代理小模型训练迭代；与训练器的交接是文件导出级，无训练中在线选数/混配。
4. 单机与 Ray 算子存在双轨（`ray_bts_minhash_deduplicator` 等 Ray 专属变体）；可选依赖面沉重。

## 3. DataFlow：数据准备的「语义层」

### 3.1 基本盘

北大 **Wentao Zhang 组（PKU-DCAI）** 主导，贡献者来自港科大、中科院、上海 AI Lab、百川、蚂蚁。~7.3k stars、Apache-2.0，PyPI `open-dataflow`，2025-06 公开发布，月度发版。技术报告 arXiv:2512.16676；子系统进了 ICDE 2026（Text2SQL-Flow）、ACL Findings 2026（AgenticRAGTracer）、KDD 2026。拿过 ICML 2025 自动数学推理挑战赛 Track 2 冠军与 BAAI 2025 语言与智能挑战赛冠军——**在「推理数据合成」这个当前最热的赛道上有实证战绩**。

核心抽象：**Operator**（实现 `OperatorABC`，注册进 `OPERATOR_REGISTRY`，当前 **~197 个、14 类**）组合成 **Pipeline**——**纯 Python、刻意 PyTorch 风格**（`__init__` 里实例化算子并注入 `llm_serving` 与 prompt 模板，`forward()` 顺序执行；`compile()` 做跨算子的键匹配静态校验）。**没有 YAML DSL**。状态经 `FileStorage`（pandas 步进缓存：jsonl/json/csv/parquet）传递。

### 3.2 流水线目录（今天就能跑的）

- **文本**：`text_pt_filter/synthetic`（预训练）、`text_sft_filter/synthesis`、`text2qa`、对话合成、`func_call_synthesis`（函数调用数据）
- **推理**：`reasoning_math`（含 MathFusion 变体）、`reasoning_general/pretrain/diy`——CoT 答案生成、难度/类别标注、验证过滤
- **Text2SQL**：生成/精化两条，底层 Text2SQL-Flow（ICDE 2026）
- **知识库清洗（KBC）**：文件/URL → Markdown（含 MinerU 式解析）→ 分块 → 清洗 → **多跳 QA 生成**
- **Agentic RAG**：多跳核心流水线（ACL Findings 2026 的基础）
- **代码**：代码数据集生成、code→SFT、代码预训练过滤
- **端到端 CLI 产品**：**`pdf2model_pipeline` / `text2model_pipeline`（PDF → 直接训出模型）**——这两个命令本身就是「垂直切片产品」的雏形
- 多模态拆在独立年轻仓库 **DataFlow-MM**（~49 stars，尚不成熟）

### 3.3 LLM 算子与后端

重度混合：LLM 驱动的合成/判审算子（`ReasoningQuestionGenerator`、LLM-judge 过滤器、`SQLVariationGenerator`、`CondorGenerator`、`AlpagasusFilter`）是主体；经典算子集中在 `general_text`（62 个：MinHash/SimHash/CCNet 去重、启发式过滤、Presidio PII），另有**训练出的打分器**（Perplexity、**QuRating、FineWeb-Edu、Deita、Superfiltering**、reward-model `RMFilter`）。LLM 服务经 `LLMServingABC` 可插拔，**13 种实现**：OpenAI 兼容 API、LiteLLM 多供应商、Vertex/Gemini、**vLLM、SGLang** 本地、VLM/音频/嵌入服务。

### 3.4 DataFlow-Agent → Harness（NL→Pipeline 的工程化）

技术报告里的 DataFlow-Agent：自然语言 → 数据分析 → 流水线规划 → 算子推荐/**合成新算子** → 迭代验证调试。2026 年演化为 **DataFlow-Harness**（2026-07 发布）+ WebUI：**Skills 层（算子选择的过程性知识）+ MCP Server（暴露算子注册表）+ 外部编码代理（Claude Code、Codex、Cursor）生成 DataFlow Python 代码**，DAG 画布可视化编辑；12 任务数据工程基准上**端到端通过率 93.3%**。姊妹仓库 **DataFlex**（~2k stars）做**训练时动态选数**——这是「内循环」数据干预的现成组件。

### 3.5 短板

1. **规模**：单节点 pandas + 每步本地文件缓存；`rayorch` 只是 ~370 行的实验性 Ray actor 封装。分布式故事与 DJ 差一个代际。
2. **多模态薄**：核心库 vision 1 个算子、speech 1 个，指望 DataFlow-MM 但其尚幼。
3. **成本**：流水线 LLM 调用密集（多步判审+合成），API 并发只是线程池。
4. **生产化**：无血缘/元数据存储、无调度器集成、测试薄、1.0.x API 快速变动；效果数字多为自报。
5. **Agent 依赖外部**：NL2Pipeline 把推理外包给第三方编码代理，自身无独立规划器。

## 4. 对比总表与互补结构

| 维度 | NeMo（Curator+训练栈） | Data-Juicer | DataFlow |
|---|---|---|---|
| 执行底座 | **Ray**（26.02 起，Xenna） | **Ray**（原生，最深） | pandas 单机（rayorch 雏形） |
| 算子形态 | 启发式+分类器，GPU 加速 | 230 个，统计/启发式为主 | ~197 个，LLM 语义为主 |
| 配置形态 | Python（Fiddle） | YAML 配方 | Python（PyTorch 风格） |
| 多模态 | 4 模态（视频强） | 4 模态 + DJ-SORA/VLA（最强） | 薄（拆到 MM 仓库） |
| 数据合成 | DataDesigner（闭源倾向） | 单调用级 mapper | **多阶段领域流水线（最强）** |
| 质量评估 | 过滤器，无归因 | Analyzer + 统计画像 | LLM-judge + 训练出的打分器 |
| 训练/RL | **全栈（唯一）** | 无（交接文件） | 无（但有 DataFlex 选数） |
| 闭环 | 无 | **Sandbox（原型，已证涨点）** | Agent 迭代验证（单机） |
| Agent/MCP | 无 | MCP ✅ + agents 套件 | MCP ✅ + Harness（93.3%） |
| 硬件 | CUDA 锁定 | CPU/GPU 混合，云中立 | API/vLLM，云中立 |
| 许可 | 开源+闭源混合 | Apache-2.0 | Apache-2.0 |

**结构性结论**：
- 三者在「数据 → 模型」链路上占据**不同层**，重叠远小于互补。
- 两个开源项目（DJ、DataFlow）都已暴露 MCP 与插件机制——**整合不需要 fork 任何一方**，胶水可以全部长在外面。
- 三方 2025–26 同时收敛到 Ray，统一执行底座首次成为现实选项。
- 链路上真正缺失、且三方都没做的：**统一样本模式与血缘、成本感知的跨框架编排、「数据切片↔评测增益」归因、配方资产管理**。这四件事就是产品。
