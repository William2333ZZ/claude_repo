## 1. 总体结构

```
datafoundry/
├── schema.py        统一样本模式 + 逐样本血缘(trace)
├── registry.py      算子协议(kind/成本档/预期留存)与注册表
├── ops/             内置算子(全自研):
│   ├── filters.py     长度/符号比/重复度/屏蔽词/质量分/质量阈值/数学答案验证
│   ├── mappers.py     空白归一/HTML剥离/PII脱敏
│   ├── dedup.py       精确去重 + MinHash-LSH 近重复去重(标准库实现)
│   └── judge.py       LLM 判审(OpenAI 兼容后端,llm 成本档)
├── pipeline.py      流水线表达(自持) + 漏斗编译器 + 成本预估
├── runner.py        执行器:output/rejects/manifest 三件套
├── engines/         开源引擎适配层(薄):datajuicer(经 dj-process CLI,可选安装)
├── security.py      鉴权原语(开源组件:argon2-cffi + PyJWT)
├── store.py         SQLite 元数据:用户/API Key/数据集/运行/审计
├── server.py        FastAPI HTTP API(RBAC 三角色)
├── mcp_server.py    Claude Code MCP harness(stdio,HTTP API 的薄客户端)
└── cli.py           serve / mcp / create-user / demo
```

测试:`tests/` 26 例,覆盖鉴权、算子、漏斗编排、端到端运行、RBAC、MCP 协议。

## 2. 关键设计决策

### 2.1 配方表达自持,执行引擎可插

流水线写成平台自己的最小表达(`steps = [{"op": ..., "params": ..., "pin": ...}]`),
不写在任何第三方框架的语言里——这是 docs/04 的核心纪律:**配方是资产,资产不能存在别人的抽象上**。
执行时:
- `engine=native`:自研算子引擎,带漏斗编排 + 逐样本血缘
- `engine=datajuicer`:把 DJ 配方(`{"process": [...]}`)经 `dj-process` 子进程执行(开源 Apache-2.0,
  `pip install py-data-juicer` 后可用;未装时报错并给指引,平台其余功能不受影响)。
  配置文件用 JSON 写出(JSON 是 YAML 子集),连 yaml 依赖都不引入
- 后续引擎(DataFlow 算子包装、Ray 分片执行)沿同一接口扩展

### 2.2 漏斗编译器(economics as code)

`funnel_compile` 按成本档稳定排序 heuristic(≈分/GB) < model(≈元/GB) < llm(≈元/千样本),
`pin: true` 可锁定顺序。`estimate` 同时给出朴素顺序和漏斗顺序的成本对比。
demo 中 10 万样本、9 步流水线含一个 LLM 判审:朴素 1500 单位 → 漏斗 803 单位,**省 46%**。

### 2.3 血缘即审计

每条样本的 `trace` 记录每个算子的动作(pass/kill/edit/score)与理由;被杀样本不消失,
进 `rejects.jsonl` 带死因。manifest 记录每算子进出/留存/耗时/成本。
这三件套同时服务:质量归因(哪步杀了什么)、合规审计(PII 何时脱敏)、配方调参(留存曲线)。

### 2.4 鉴权:开源组件,不自研密码学

| 环节 | 组件 | 说明 |
|---|---|---|
| 口令哈希 | **argon2-cffi**(Argon2id) | OWASP 首选;哈希串自带盐;登录时自动 rehash 升级参数 |
| 会话令牌 | **PyJWT**(HS256) | 服务端随机密钥(0600 文件),12h 过期,带 jti |
| API Key | `dfk_` + 32B 随机 | 库中只存 SHA-256 哈希,明文只展示一次,可吊销 |
| RBAC | viewer < engineer < admin | viewer 只读;engineer 上传/运行/管 Key;admin 管用户 |
| 引导 | `POST /auth/bootstrap` | 仅在零用户时可用,创建第一个 admin;或 CLI `create-user` |
| 审计 | audit 表 | 登录、建用户、发 Key、上传、运行全记录 |

**升级路径**:企业 SSO 走 OIDC 对接开源 IdP(Keycloak/Casdoor);资源级授权引入 pycasbin。
**诚实的边界(v0 未做)**:速率限制、登录失败锁定、TLS(交给反代)——生产部署前先补这三件。

### 2.5 MCP harness:Agent 的能力 = 其 Key 的角色

`datafoundry mcp` 是 stdio MCP 服务(JSON-RPC 2.0 自实现,零额外依赖),
但它只是 HTTP API 的薄客户端:**所有权限判定都发生在服务端**,Claude Code 拿到的能力
严格等于 `DATAFOUNDRY_API_KEY` 对应用户的角色——viewer 的 Key 连上传都调不动。
8 个工具:`df_status / df_list_operators / df_list_datasets / df_upload_dataset /
df_inspect_dataset / df_estimate_pipeline / df_run_pipeline / df_get_run`。
工具描述里内嵌了「先估后跑」的引导,Agent 会自然形成 估成本 → 跑漏斗 → 看死因 → 调参 的循环。

## 3. 快速上手

```bash
pip install -e .                      # 或 pip install -e ".[dev]" 跑测试
datafoundry demo                      # 离线演示:脏数据 -> 漏斗 -> 报告(不需要账号)

datafoundry serve                     # 起服务(默认 127.0.0.1:8321)
curl -X POST localhost:8321/auth/bootstrap \
  -H 'Content-Type: application/json' \
  -d '{"username":"root","password":"<你的口令>"}'   # 首次:创建 admin
# 登录拿 token -> POST /auth/keys 拿 dfk_ 开头的 API Key
```

接入 Claude Code:

```bash
claude mcp add datafoundry \
  --env DATAFOUNDRY_URL=http://127.0.0.1:8321 \
  --env DATAFOUNDRY_API_KEY=dfk_xxx \
  -- datafoundry mcp
```

之后在 Claude Code 里直接说"检查一下 ds_xxx 的质量,设计一条清洗流水线,先估成本再跑"即可。

## 4. v0.1 边界与下一步

| 已做 | 未做(按优先级) |
|---|---|
| 自研算子引擎 + 漏斗 + 血缘 | 验证器族扩展(代码沙箱执行、SQL 执行比对)——docs/04 的第一优先级 |
| RBAC 鉴权(开源组件)+ 审计 | 评测闭环(小代理模型训练 + 评测集回流 manifest) |
| MCP harness(8 工具,烟测通过) | judge 标注 → 蒸馏小打分器的产线 |
| DJ 开源引擎薄适配 | DataFlow 算子包装、Ray 分片执行器(接口已留) |
| 26 例测试 | 速率限制/登录锁定;OIDC SSO;Web 控制台 |

单机上限 50 万样本(超限明确报错)。所有依赖均为开源:fastapi、uvicorn、PyJWT、argon2-cffi(必装),
py-data-juicer(可选)。闭源组件零依赖——这条红线写进 `engines/__init__.py` 的模块注释里,谁改谁负责。
