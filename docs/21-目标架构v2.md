## 0. 主链与安全线(整图的一句话)

**主链:意图 → 配方提案 → 授权 → 精炼事实。**

- ① **意图**(人 / AI / Mission):「把这批文档变成能训的 SFT 数据,预算 X」
- ② **配方提案**(AI 组装):算子链 + 成本预估 + 预期死因分布 + 风险提示;算子注册表裁决合法性 ✅
- ③ **授权**(只有人):批准配方版本 + 预算上限 + 交付门槛;所见即所签 = 配方内容 hash(#16)🔶
- ④ **精炼事实**(只有系统):run 执行,逐样本 trace 追加不可改,manifest 记录配方版本与指纹 ✅

**安全线(DataFoundry 版,与 BMS 差异见 §5)**:
1. LLM 判审**永不单独杀样本**——处置权属于验证器(确定性)或已授权配方中的阈值;每杀必留死因 ✅
2. AI 永不修改配方边界、永不动账本、永不放行交付 ✅(账本唯一写入点 = 支付回调幂等事务)
3. 花钱动作(LLM 调用)必在授权预算内,判审错误率 >20% 熔断 ✅
4. 对外主张必可复现(seed + sha256 + run id),不可复现的不外发 ✅(C2 纪律)

**一句话**:原生的是认知,确定的是裁决与账本。

配方 hash+效果档案的纯数据工程)。认知会随模型进步贬值,证据与档案随使用增值——建在增值的一侧

## 5. 系统五律(2026-08-15,委托人「用系统架构思维设计」指示后成文)

分层图(§1)回答「有什么」;本节回答**「什么永远不变、什么随便换」**——系统架构的本体。
组件全部可替换,只要五律成立;五律每条都有本仓库的实证锚点,不是口号。

**律一 · 不变量优先于组件**(系统=不变量的集合,组件=当前实现):
- I1 每条样本的处置必有可追溯死因(trace append-only)
- I2 裁决必确定性:同输入+同配方+**同平台版本** → 同输出(manifest.platform_version,docs/24 Q3);AI 只 advise
- I3 资金写入唯一点、同事务、幂等(mark_order_paid)
- I4 对外数字必可复现(seed + sha256 + run id)
- I5 认知可替换:agent/模型是可插拔外设,系统不依赖任一供应商
实证:P0-1 换存储后端业务零改动(I3 迁移不破);判分 bug 修复=恢复 I2/I4;
Kaggle 换卡换栈不动协议(I4);BYOK/MCP(I5)。

**律二 · 窄腰接口(narrow waist)**——复杂系统靠少数窄接口存活(互联网之于 IP):
① 样本 schema(id/text/meta/stats/trace)——算子只见它
② 算子协议(process/expand + 注册表元数据)——runner 与算子解耦,DJ 引擎也从这进
③ 事实文件族(output/rejects/manifest/judge_labels)——审计/评测/档案/agent 只读它
④ 认知接入面 = REST API(技能剧本直驱;MCP 为可选适配器,df_* 是其投影)——一切认知体只从这进(docs/26 §7)
四条窄腰之外,一切实现可翻新(流式化 #13 全程未动任何窄腰,即证)。

**律三 · 反馈回路是发动机**(护城河=回路的积分,非任一组件):
评测回流→run(质量)· judge_labels→蒸馏→便宜算子(成本)· rejects 死因→配方修正
(配方)· 纠错→纪律成文(治理——本文档两次委托人纠错即该回路的实例)。

**律四 · 降级路径实测过才算数**:LLM 挂→零 LLM 漏斗(62.5 分实测)· agent 不在→
CLI/API 直用 · PG 不可达→SQLite 本地 · Actions 挂→本地复现路径(docs/20 §7 路径 B)。
每个外部依赖配一条**有实验分数或有演练记录**的退路。

**律五 · 演进是规则不是蓝图**:gate 门禁 · L 必拆 · 触发条件制(#14/#18 立册不开工)·
文档退役 · 复验纪律。架构约束「变更如何发生」,不预言终态。

## 6. 与 BMS 的一处根本相同与一处根本不同

**相同**:两者都把「AI 的边界」当作架构的第一块石头——不是能力清单,是禁令清单。我们的禁令
有实验背书(判审 vs 验证器杀伤率 8.3%/100%),这是本架构最硬的一块。

**不同**:BMS 的事实是业务台账(人授权每条);我们的事实是数据处置记录(验证器依授权配方
批量裁决)。**授权在配方,裁决在验证器,记录在事实流**——三权分立按数据规模重新切分。

## 7. 域图与包边界(2026-08-15,委托人「我们是否也该设计域和包」之问后定案)

dsh 解剖(221 包/26 域/45 万行)给的教训不是"多分包",是**边界跟着接缝走、规则由测试守护**。
我们 3,891 行,规模解不同,原则相同——**域立刻立(纪律形式),包不拆(部署边界是唯一拆包理由)**:

| 域 | 成员 | 顶层依赖规则 |
|---|---|---|
| kernel 精炼内核 | schema/registry/pipeline/runner/recipes/matheq/audit/ops/engines | **只许 stdlib+kernel(零第三方,可嵌入的结构保证)** |
| service 服务壳 | server/store/security/billing/ratelimit | 可用第三方与 kernel;禁引 interface |
| interface 薄客户端 | cli/mcp_server/credentials | stdlib+kernel;服务只走 HTTP 窄腰 |

可选依赖(sympy/psycopg/alipay)只许函数内懒加载;Data-Juicer 引擎走 subprocess 连 import 都不需要。
**守护:tests/test_domains.py 五条测试**——AST 逐文件核顶层 import,越域/顶层第三方/包
`__init__` 污染/新模块未归类,一律响亮失败(dsh"缺服务=组装错误 fail loud"的我们版本)。
2026-08-15 首跑即绿:平铺布局本已干净,今起由测试而非自觉维持。
