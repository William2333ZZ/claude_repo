# 20 · M1-C2 公开复现报告:同预算下,漏斗+验证产线对三条常规产线

> **本报告是 gate #7 的判定文书**,回答一个可判真伪的问题:
> **同一语料、同一预算,「漏斗+硬验证」产线能否稳定训出更高评测分?**
> 答案:**能(限定主张,见 §1)。** 全部数字可复现:每个数字带运行 ID 与种子,语料与评测集带 sha256。

## 1. 结论与 gate 判定

**Gate #7:通过,限定主张**(2026-08-13 报备,否决窗口无异议)。

成立的主张(四种子确立):
1. **漏斗+硬验证(arm4a)每种子都赢不清洗基座**:4/4 种子为正,最小 +10.0,均值 +14.2
2. **对同为清洗的纯启发式(arm1)逐种子完胜**:配对差均值 +17.5,t=5.68(df=3,p<0.05)
3. **方差最小**(3.5,对照 5.9/9.1):净数据让训练结果更可预测
4. **不带验证器的清洗平均是亏的**:arm1 均值 −3.3,仅 1/4 种子为正——「清洗」不等于「提质」,**验证器是正负回报的分界线**

不成立/不宣称的主张:
- 对打分器(arm3)只说「均值更高且更稳」:配对 t=1.88 未超噪声,**不称显著优于**
- arm3 的 gain-per-cost 比值在均值口径下更高(成本极小所致),但其回报不稳定(1/4 种子为负,σ=9.1)——gate 判据是「**稳定**做出更高分」,arm3 败在稳定性
- 3B 上的 +3.3 在 60 题粒度(1 题=1.67 分)下不解读

## 2. 实验设计

**语料**:确定性生成的中文小学数学 QA,5,000 条,受控注入六类:clean 3,000 / wrong_answer 750 / spam 400 / offtopic 350 / dup 250 / near_dup 250(唯一题面 4,500)。隐藏标签 `_gt` 仅用于事后杀伤率分析,产线不可见。
**五组产线**(同预算口径,数据侧成本按平台成本单位计):

| 组 | 机制 |
|---|---|
| arm1 | 纯启发式:规则清洗 + 精确去重 |
| arm2 | 精确去重 + **全量 LLM 判审**(deepseek-chat) |
| arm3 | FineWeb-Edu 风格质量打分器阈值筛选 |
| arm4a | **漏斗:启发式 → 去重 → math_answer_verify 硬验证**(零 LLM) |
| arm4 | arm4a + LLM 判审收尾(判审只看漏斗幸存者) |

**训练协议**(组间唯一变量=数据):Qwen2.5-0.5B-Instruct,LoRA r8/α16/dropout 0.05(q/k/v/o),lr 2e-4,2 epoch,batch 1×累积 8,采样上限 1,000,MAX_LEN 320,种子经 `TRAIN_SEED` 注入。
**评测**:math_zh_v1(60 题),贪心解码,精确匹配,判分器 `eval_math.score`(全自动零人工)。

|---|---|---|---|---|---|---|---|---|---|---|

## 4. 结果 B:LLM 判审组,双种子(DeepSeek deepseek-chat)

运行:31678278278(s42)/ 31690175109(s43)。judge 错误率熔断(>20%)未触发。

| 组 | s42 | s43 | 均值 | vs 基座 | judge 调用(恒定) | 数据成本(s42) |
|---|---|---|---|---|---|---|
| arm2 全量判审 | 58.3 | 60.0 | 59.2 | +10.9 | 4,737 | 71.06 |
| arm4 漏斗+验证+判审 | **70.0** | 66.7 | **68.4** | **+20.1** | 2,435 | 36.56 |

**三个发现(双种子复现)**:
1. **全量 LLM 判审打不过零 LLM 硬验证**:arm2 两种子均 ≤ 同种子 arm4a,而成本差约 **2,000 倍**(71.06 vs 0.035)。机制:judge 对 wrong_answer 的杀伤率仅 **8.3%**(验证器 100%),near_dup 仅 6.4%(判审不会去重)
2. **arm4 全场最高**(68.4,全五组、六个种子口径):验证器杀错答(100%)+ judge 补杀 offtopic 尾巴 + 去重除重——三类算子各干强项,漏斗按成本排序
3. **漏斗省判审实测**:judge 只看幸存者,调用省 **48.6%**(2,435 vs 4,737),总成本约一半,分数反高(+11.7 / +3.4)
副产物:judge_labels 蒸馏语料 +7,172 条;两组合计 ≈7,172 次真实 API 调用,现金成本 ≈¥5。

## 5. 结果 C:3B GPU 复验(方向性证据)

Kaggle P100(fp16 自愈路径:torch 2.4.1+cu118,transformers 4.46.3),seed 42,协议与 0.5B 完全一致。运行:31722654011(arm4a)/ 31725874168(baseline);分数经离线复判(31726292053 / 31727863389)。

| 尺度 | 基座 | arm4a | Δ |
|---|---|---|---|
| 0.5B | 48.3 | 58.3(s42) | +10.0 |
| 3B | 80.0 | 83.3 | +3.3(噪声边缘) |

**方向为正(2/2 尺度),幅度不解读。** 本轮主发现是**天花板效应**:3B 基座已 80 分,评测集对它太容易,数据质量的增量空间被压缩——推论:①数据精炼的价值在「模型还不会的领域」最大;②更大模型需更难评测集(→ issue #12 math_zh_v2)。

## 6. 机制:死因杀伤率(隐藏标签 `_gt` 事后核对)

| 噪声类型 | arm1/arm3 | arm4a 验证器 | arm2 全量判审 |
|---|---|---|---|
| wrong_answer(15%) | 17–19% | **100%** | 8.3% |
| offtopic | — | 96.6% | 96.6%→100%(arm4 补杀) |
| near_dup | 去重可杀 | 去重算子 | 6.4% |
| clean 误杀 | — | **0** | — |

常规产线对「错误答案」几乎无能为力,训练把错误教进模型——这就是 arm1 均值为负的机制。

## 8. 局限(如实携带)

1. 合成噪声 ≠ 真实语料噪声分布;评测集自建且考训同模板族(绝对分虚高,相对比较有效)
2. 0.5B 代理为主证据;3B 单种子方向性;7B 未跑(待 T4)
3. 60 题粒度:±2–3 分内的差异一律不解读
4. LoRA-on-Qwen 存在预训练知识混淆因子——从零预训练证伪(MiniMind 26M,C1d)在册未跑
5. 成本为平台抽象单位;零 LLM 组绝对成本极小,其成本差异的商业含义有限

**证据升级路径**:T4 7B(一键待执行)→ math_zh_v2 难度升级(#12)→ 真实语料复验 → C1d 从零证伪。

## 9. 事故与修正记录(方法论透明)

本实验期间发生并修复的仪器事故,全部留档:
- **单种子过强叙事两次被复验纠正**(首轮「常规产线必负回报」、两种子期「4a 显著>3」)——催生「±2-3 分不解读」纪律
- **Kaggle 轮询大小写 bug** 致 4.5h 僵尸等待——修复后失败 10 分钟内可见
- **判分口径 bug**(str/int 手写比较)致 3B 首报 0 分——generations 逐题证据显示模型输出全对,离线复判追回真实分数;判分自此单源化到 `eval_math.score`
教训一句话:**异常分数先怀疑仪器,再怀疑模型;监控只盯成功信号等于没有监控。**
