# 14 · 商业化方案(产品域全权)

> 依据委托人 2026-08-13 裁定:**商业化归产品域负责,产品作为项目的全权负责**(治理修订见
> docs/09 §5.2)。本文是产品说明中此前缺失的商业化全案——把"什么算好"(docs/02)与
> "什么能卖、卖给谁、怎么收钱"接成一张图。docs/02 §6 保留为模式概览,细节以本文为准。

## 1. 为什么商业化必须归产品

定价与打包不是销售动作,是**产品定义的延伸**:额度怎么计、PoC 包里装什么、报告哪些部分
公开——每一条都在回答"产品的价值单位是什么"。拆成两个域会出两张皮:产品定义"什么算好",
商业另说"什么能卖"。并入后,一个 Owner 同时对两个问题负责,gate 判定与定价判定同源。

## 2. 卖什么:可售卖物清单(与 docs/12 产品矩阵对齐)

| 形态 | 商业角色 | 收费方式 | 状态 |
|---|---|---|---|
| 开源内核(Apache-2.0) | **不卖**——生态位与信任资产,获客漏斗的顶部 | 免费 | ✅ 可用 |
| 技能包 + harness 接入(Skill/REST 直驱;MCP 可选) | **不卖**——入口体验,把 Agent 用户引进平台 | 免费 | ✅ 四件套已落库 |
| 托管实例 | 自助订阅的载体 | 额度包(下表)→ 年费订阅 | 🟡 测试级,P0-1 修复后才可承接付费 |
| **配方包**(买断制) | 类 boilerplate 售卖:一个领域的完整配方+评测集+复现实验报告 | 买断,几百到几千元/包 | 🟡 首个雏形 = math 配方(arm4a 全套),C2 报告即其说明书 |
| **垂直交付**(M3-H1) | 「文档→模型」一键交付,早期现金流主力 | 项目制或订阅 | ⚪ gate 后打包 |
| 商业外壳(TinyShip) | 收银台与官网,**是渠道不是商品** | — | ⚪ gate 后购建 |
| 公开报告(C2) | **营销资产**:可复现=可信,build in public 首发内容 | 免费公开 | 🟡 4 种子中 2 已完成 |

核心售卖逻辑:**开源内核建信任 → 公开报告证效果 → 配方包/额度包自助成交 → 垂直交付与年费
订阅做大单**。凡是"判断类核心资产"(评测口径、验证器、归因)只进付费层,不进开源层(docs/04)。

run 创建时按估算扣减——额度即"数据精炼的算力当量",与漏斗编译器的省钱卖点同一套语言。

|---|---|---|---|

judge_labels 蒸馏语料,数据产线不是一次性问答——用得越多,配方与判别器越准。

## 5. 单位经济(现状实测)

- **获客边际成本 ≈ 0**:公开报告与文档站即营销,build in public,无投放
- **交付边际成本极低**:实验与 CI 全在 GitHub Actions 免费跑器(C2 报告的数据生产成本为零);
  托管当前 Render 免费档
- **承接付费的前置成本**(gate 后首批):Render 付费档 + 持久盘/托管 PostgreSQL(P0-1),
  量级 $7–20/月——第一单 PoC 即覆盖两个数量级
- **毛利结构**:自助额度包近纯毛利;垂直交付吃人力(AI 执行单元压低);LLM 判审成本可经
  漏斗后置与蒸馏(judge_labels 已在采集)持续压降——**成本优化本身就是产品功能,也是毛利来源**

5. 所有收费动作(定价变更、开单、退款)走审计日志——账本在内核,收银台在外壳

## 9. 价值链站位:下游边界(2026-08-13,委托人提问后裁定)

价值链:原料 → ①数据集 → ②模型 → ③应用 → 业务结果。裁定:

1. **站位 = ①+②全包**:「数据 → 模型 → 评测报告」是同一闭环的出口(M3-H1 交付本质是卖模型
   交付而非数据集);每个交付模型都向归因档案添一条「配方×数据×分数」,复利资产照转
2. **③应用层不做**,三个理由:竞争面反转(从 P1 的补给商变竞争者,渠道冲突杀死访谈与 PoC)、
   复利断裂(平台赌注=跨客户网络效应,应用赌注=单垂直纵深,gate 前双押必双输)、资源现实
3. **两个例外**:灯塔展示品(gate 后,限一个,营销资产预算级)与白标拉动(P3 触发条件不变)
   ——灯塔首选候选(2026-08-13):**「漏斗精炼语料 → MiniMind 26M 从零训练 → 4bit GGUF → ESP32-S3 离线问答」**,全链成本 <¥100,是「数据质量决定模型」的最便宜全栈实证,亦服务 P4 假设验证
4. **远期真理由留档**:应用是唯一产生真实使用反馈(偏好对/采纳率)的地方——RL 时代的数据
   飞轮闭合器。**重估触发:归因档案跑通 + 客户拉动信号**(PoC 客户主动要求运营到应用层)
5. 定价咬合 §8 价值锚:②模型交付按「训练保险制」试价——离结果近一格,就按结果的语言收钱

## 10. 商业逻辑升级:收费边界原则(2026-08-13,学 LangAlpha,委托人指示)

LangAlpha 商业逻辑四条:软件全栈开源(代码不是护城河)、收费画在"自托管复制不了的
持续累积资产"上(实时行情 feed/always-on 自动化)、BYOK 不站在客户与智能成本之间、
开源即分发(零获客)。据此裁定:

1. **收费边界原则**:软件功能不是收费边界,**持续累积的稀缺资产**才是。四个收费支柱:
   ①**证据档案订阅**——配方×数据×分数的归因档案,活的、跨客户累积(我们的"行情 feed";
   归因=护城河本体再获一票)②**合规模板持续更新订阅**——TC260/EU 条款变化即推送新审计
   模板,监管在替我们制造复购 ③**always-on 托管运营**——定时精炼/漂移监控/自动重审计
   ④交付服务(M3-H1)。**额度制降级为托管计量工具,不再是商业模式本体**
2. **配方包双形态**:快照买断(入门)+ **活档案订阅**(证据随全网运行持续更新)——
   一次性收入升级为经常性收入
3. **BYOK 商业含义**:报价与模型降价脱钩——token 越便宜,客户精炼越多,档案越值钱;
   对智能成本波动结构性免疫
4. **升级阶梯长进架构**(学其 add keys incrementally):免费自托管+BYOK → 档案只读 →
   档案订阅+合规推送 → 托管运营 → 交付;每档能力缺口对应一个付费动作
5. **D3 重估砝码加重**:此逻辑完整成立依赖全栈开源换分发;**TinyShip 采购决策前必须
   先裁"自建开源外壳+档案收费"路线**(docs/19 D3 触发条件升级为前置审查)
6. **两轴定价结构**(2026-08-13 官网一手证实,docs/19 §1.5):**订阅费=能力开关**(档案
   访问深度/合规推送/定时精炼任务数/工作区数/API),**计量费=托管资源**(用我们的跑器
   或托管模型时才扣额度),**BYOK 完全免计量**。价格量级校准:它自助档 $20/40/100 月付
   ——我们 ¥99/¥499 额度包在同一量级,PoC ¥9,900 是 B2B 物种不冲突;年付 -15% 惯例采纳

## 11. 立意与定位:「用户为什么选我们」的苏格拉底推演(2026-08-14,委托人命题)

八问链(完整推演见当日会话,此处存结晶):

1. 用户是谁 → 不是「垂直模型团队」这个抽象类,是**三张具体的脸**:拿季度赌一次微调的
   算法负责人 / 要在备案表上签字的合规负责人 / 被 token 账单追着跑的 Agent 公司 CTO
2. 没有我们他们怎么活 → 开源工具拼凑(DJ/DataFlow 算子管够)或不清洗直接训——**活得下去**。
   所以我们不是「工具缺口」生意
3. 哪一刻疼 → **「钱花了、分数没涨、说不清为什么」**的那一刻(四种子实证:不带验证器的
   清洗平均是亏的,arm1 −3.3)。疼点不是数据脏,是**不可归因的失败**
4. 那一刻缺的是工具还是答案 → 答案。「这批数据值得训吗?哪条在害我?训砸了怪谁?」
   ——**我们卖的不是清洗,是可辩护的判决**(死因/血缘/审计/评测闭环)
5. 为什么不是免费的 Data-Juicer → DJ 给 100 把刀,我们给「这刀砍对了吗」的判决书。
   开源算子是零件,**带质检报告的产线**才是产品;竞对是「说不清为什么」,不是 DJ
6. 判决书凭什么可信 → 全部可复现(seed+sha256+run id),5 分钟试驾亲手摸,
   「你验证它,而不是信一个黑箱」(与 LangAlpha 信任叙事同构,docs/19 §1.5)
7. 模型越强是不是越不需要我们 → 反了。天花板效应实证(3B 基座 80 分):模型越强,
   通用数据越不值钱,**「模型还不会的垂直域」的净数据越值钱**;且验证器/评测集是模型
   无法自我提供的外部判据——水位上涨,露头的岛更贵
8. 第一次付钱买什么,第二次呢 → 第一次买止痛(一次交付/一份合规审计);第二次买复利
   (配方证据档案+judge_labels 越用越准)。**没有第二次就是项目公司**——档案订阅(§10)
   是产品公司的那条命

**立意一句话**:让每一条训练数据的去留都有可辩护的理由。
**定位陈述**:DataFoundry 是训练数据的品控与归因层——不替你写模型,替你回答
「这批数据值不值得训、坏在哪、谁负责」,答案可复现、可审计、可积累。

**推广三主张**(每条挂一个可复现数字,红线:不可复现的不外发):
- 「不带验证器的清洗,平均是亏的——我们量过」(arm1 四种子 −3.3,1/4 为正)
- 「同预算,漏斗+验证稳定高 14 分,且逐种子全正」(arm4a +14.2,4/4)
- 「LLM 判审费省一半,分反高:因为漏斗只让幸存者见裁判」(判审调用 −48.6%,+11.7)

**推广的第一 KPI 不是流量,是 3 个访谈样本**(H3 金标准缺口是当前定位的最大不确定):
C2 报告发布(委托人放行)→ 每渠道文末挂访谈邀约 → P-agent 证据扫描(AI 自主)出接触
名单 → M3-H2。渠道次序:技能包分发(skills/ 拷贝即用)+ MCP/Claude 目录收录 + DJ/DataFlow 上游 PR(生态旗舰,docs/19
D5)> 知乎/公众号长文(合规角度切入,H2 法定需求)> HN/X(英文版随出海裁定)。

### §11.1 价值可感知性(2026-08-15,委托人追问「非专业人员是否意识不到价值」)

**前提成立且更狠:分界线不是专业/非专业,是疼过/没疼过**——arm1 的 −3.3(清洗反伤模型)
在实验前连多数专业工程师也不信。防止「看不见的失败」的仪器类产品(灭火器/审计/保险)
从不靠大众意识到价值,靠三杠杆,一个都不靠教育市场:

1. **事故后购买**:P1 筛选问题定为「有没有一次训练结果你解释不清」——只找疼过的
2. **法定强制**:TC260/EUAI 是**免费的价值翻译官**——合规负责人不必懂验证器,只需知道
   备案要证据链(docs/16 H2 双法定的战略意义在此)
3. **代理指标翻译,对外叙事双语制**:每条专业主张配老板版——
   「arm1 −3.3」→「花钱清洗可能把模型越洗越差,我们量过」;
   「省判审 48.6%」→「AI 质检费砍一半,分数反升」;
   「逐样本死因血缘」→「训砸了能查出是哪批数据的责任」
