# 14 · 商业化方案(产品域全权)

> 依据委托人 2026-08-13 裁定:**商业化归产品域负责,产品作为项目的全权负责**(治理修订见
> docs/09 §5.2)。本文是产品说明中此前缺失的商业化全案——把"什么算好"(docs/02)与
> "什么能卖、卖给谁、怎么收钱"接成一张图。docs/02 §6 保留为模式概览,细节以本文为准。

## 1. 为什么商业化必须归产品

定价与打包不是销售动作,是**产品定义的延伸**:额度怎么计、PoC 包里装什么、报告哪些部分
公开——每一条都在回答"产品的价值单位是什么"。拆成两个域会出两张皮:产品定义"什么算好",
商业另说"什么能卖"。并入后,一个 Owner 同时对两个问题负责,gate 判定与定价判定同源。

## 2. 卖什么:可售卖物清单(与 docs/12 产品矩阵对齐)

| 形态 | 商业角色 | 收费方式 | 状态 |
|---|---|---|---|
| 开源内核(Apache-2.0) | **不卖**——生态位与信任资产,获客漏斗的顶部 | 免费 | ✅ 可用 |
| Claude Code harness(MCP) | **不卖**——入口体验,把 Agent 用户引进平台 | 免费 | ✅ 可用 |
| 托管实例 | 自助订阅的载体 | 额度包(下表)→ 年费订阅 | 🟡 测试级,P0-1 修复后才可承接付费 |
| **配方包**(买断制) | 类 boilerplate 售卖:一个领域的完整配方+评测集+复现实验报告 | 买断,几百到几千元/包 | 🟡 首个雏形 = math 配方(arm4a 全套),C2 报告即其说明书 |
| **垂直交付**(M3-H1) | 「文档→模型」一键交付,早期现金流主力 | 项目制或订阅 | ⚪ gate 后打包 |
| 商业外壳(TinyShip) | 收银台与官网,**是渠道不是商品** | — | ⚪ gate 后购建 |
| 公开报告(C2) | **营销资产**:可复现=可信,build in public 首发内容 | 免费公开 | 🟡 4 种子中 2 已完成 |

核心售卖逻辑:**开源内核建信任 → 公开报告证效果 → 配方包/额度包自助成交 → 垂直交付与年费
订阅做大单**。凡是"判断类核心资产"(评测口径、验证器、归因)只进付费层,不进开源层(docs/04)。

## 3. 卖给谁:客户分层与购买旅程(docs/02 §2 落地)

| 层 | 客户 | 首次成交物 | 旅程 |
|---|---|---|---|
| P1 | 垂直模型团队(金融/法律/医疗/制造,10–100 人) | **PoC 包 ¥9,900** → 年费订阅 | 公开报告 → 五分钟试驾(docs/07)→ 访谈 → PoC → 订阅/交付 |
| P2 | 开源微调者 / AI 应用公司 | 配方包或入门额度包(自助) | 报告/README → 自助下单,零销售介入 |
| P3 | 数据服务商(白标) | 垂直交付项目 | 由 P1 案例背书后再启动,M3 不主攻 |

**购买旅程的关键设计**:每一步都已有实物承接——试驾指南(docs/07)、设备码登录、托管实例、
计费通道(docs/11)全部建成;唯一断点是支付宝应用上线(待委托人提审)与 P0-1 账本外置。
旅程与场景卡的三级保真对应关系见 **docs/15**(读报告=低保真触点,试驾=中保真,付费 PoC=高保真)。

## 4. 定价与打包 v1(代码已实现,最终价过 M3-H3 验证)

平台计价单位 = **额度(credit)**:1 样本 × 1 成本档 = 1/10/100 额度(启发式/模型/LLM 三档),
run 创建时按估算扣减——额度即"数据精炼的算力当量",与漏斗编译器的省钱卖点同一套语言。

| 档 | 价格 | 额度 | 定位 |
|---|---|---|---|
| 入门包 starter | ¥99 | 10 万 | 自助试用,P2 首单 |
| 专业包 pro | ¥499 | 100 万 | 自助主力档 |
| **PoC 包 poc** | **¥9,900** | 1000 万 | P1 首次成交物,可抵扣后续订阅 |
| 年费订阅(规划) | ¥20–40 万/年 | 按约定 | 锚:替代 60–100 万/年的数据工程师(docs/02 §6) |
| 配方包(规划) | 数百–数千元/包 | — | 买断制,TinyShip 模式的直接移植 |

**定价叙事**(docs/10,Steph Ango 路线):用户付费支撑、不做广告、不做免费增值陷阱;
对客户的一句话仍是「同样的算力预算,更高的评测分数」,漏斗省下的判审成本(演示场景 −46%)
直接量化进报价。

## 5. 单位经济(现状实测)

- **获客边际成本 ≈ 0**:公开报告与文档站即营销,build in public,无投放
- **交付边际成本极低**:实验与 CI 全在 GitHub Actions 免费跑器(C2 报告的数据生产成本为零);
  托管当前 Render 免费档
- **承接付费的前置成本**(gate 后首批):Render 付费档 + 持久盘/托管 PostgreSQL(P0-1),
  量级 $7–20/月——第一单 PoC 即覆盖两个数量级
- **毛利结构**:自助额度包近纯毛利;垂直交付吃人力(AI 执行单元压低);LLM 判审成本可经
  漏斗后置与蒸馏(judge_labels 已在采集)持续压降——**成本优化本身就是产品功能,也是毛利来源**

## 6. 收入路径与里程碑(挂接 docs/08)

| 节点 | 商业化验收 | 依赖 |
|---|---|---|
| M1-C2(gate) | 公开报告发布 = 首个营销资产上线 | 4 种子实验(进行中) |
| M3-H2 | 3 家 P1 深度访谈,**1 家付费 PoC(¥9,900 实收)** | 访谈的**低保真部分依 docs/15 §4.3 提前至 gate 前启动**(零建设零收款);付费 PoC 仍依赖 gate、支付宝上线、P0-1 |
| M3-H3 | 2 个报价方案实测反应,校准年费区间 | H2 访谈 |
| gate 不过 | 平台化冻结,商业化整体转 M3-H1 纯垂直交付形态(预案不变) | — |

**第一笔真实收入的完整链路已可演练**:下单(/billing/order)→ 支付宝当面付二维码 → 回调核账
(幂等)→ 额度到账 → run 扣减——差"应用提审上线"与"账本外置"两步,均已在 docs/12 裁定为
gate 后首批事项。

## 7. 红线与纪律(不因商业化松动)

1. **gate 前不建外壳、不采购、不收真钱**——commercial 动作与平台化同受 #7 门禁约束
2. **TinyShip 授权代码一行不进开源仓**(两仓分离,docs/10 §3)
3. **真实收款前必须完成 P0-1**(账本易失 = 收钱事故,docs/12 一票裁定)
4. **对外叙事只引用可复现数字**:报告里的每个数字带 seed 与 sha256,不可复现的不外发
5. 所有收费动作(定价变更、开单、退款)走审计日志——账本在内核,收银台在外壳
