# 13 · 技术选型决策记录(ADR 汇总)

> 全项目技术选型的唯一登记处。此前散落于 docs/02(架构)/04(依赖红线)/05(平台)/10-11(商业组件),
> 本文汇总并补齐"为什么选它、落选了谁、什么信号触发重估"。新选型一律先登记于此再动手。
> 总原则(docs/04):**闭源运行时零依赖;开源可依赖但薄适配;判断类核心自研;配方表达自持。**

## 1. 平台内核

| 领域 | 选择 | 理由 | 落选备选 | 重估触发 |
|---|---|---|---|---|
| Web 框架 | **FastAPI** | 类型化+自动 OpenAPI(/docs 即接口文档)、异步、生态大 | Flask(无类型契约)、Django(重,不需要 ORM/Admin) | 不太可能重估 |
| ASGI 服务 | **uvicorn** | FastAPI 标配,单容器够用 | gunicorn+uvloop | 多进程需求时加 gunicorn 托管 |
| 口令哈希 | **argon2-cffi**(Argon2id) | OWASP 首选;自带盐;支持参数升级 rehash | bcrypt(可用但次优)、passlib(维护趋缓)、自研(禁止) | 无 |
| 令牌 | **PyJWT**(HS256) | 事实标准;密钥文件 0600 | python-jose、自研 HMAC(初版已废弃) | 多实例部署时评估 RS256/JWKS |
| 元数据存储 | **SQLite**(v0) | 零运维、单文件、事务够用 | PostgreSQL | **已触发**:P0-1(账本易失)→ gate 后迁 PostgreSQL(Neon/Supabase 免费档),store 层已抽象 |
| 数据交换 | **JSONL**(v0)/ Arrow(规划) | 流式友好、人可读、生态通吃 | Parquet(列存,规模化时加) | 样本量 >50 万或列裁剪需求时 |
| 执行底座 | **单机内存**(v0)→ **Ray**(M2-E1) | v0 求快;Ray 是三上游(DJ/Curator/NeMo RL)共同收敛点(docs/01 §4) | Spark(JVM 栈,ML 生态弱)、Dask(Curator 已弃) | M2-E1 立项即执行 |
| MCP 服务 | **自实现 stdio JSON-RPC** | 协议薄(~150 行),零依赖;作为 HTTP API 薄客户端保证权限单点 | 官方 mcp SDK | 协议大版本升级或需 HTTP/SSE 传输时改用 SDK |
| CLI | **argparse**(标准库) | 零依赖 | click/typer | 子命令复杂化(>10 个)时 typer |

## 2. 数据与算法

| 领域 | 选择 | 理由 | 落选备选 | 重估触发 |
|---|---|---|---|---|
| 算子引擎 | **自研**(17 算子,成本三档) | 配方是核心资产,表达必须自持(docs/04 §3) | 依赖 DJ/DataFlow 框架(降级为引擎/思路) | 无——这是产品本体 |
| 去重 | **自研 MinHash-LSH**(标准库) | 零依赖;参数可按语料校准(bands 实测调优) | datasketch 库、DJ RayDeduplicator(保留为 Ray 时代零件) | 千万级样本时接 DJ 的 BTS 实现 |
| 验证器 | **自研**(math_answer_verify 起步) | 质量护城河(docs/04),外部无现成 | — | M2-D 扩代码沙箱/SymPy/SQL 双跑 |
| LLM 后端协议 | **OpenAI 兼容 HTTP**(标准库 urllib) | 一套协议通吃 vLLM/SGLang/各家 API,零 SDK | openai SDK、litellm | 需要流式/函数调用时评估 litellm |
| 代理训练(GPU) | **LLaMA-Factory**(LoRA) | 配方化微调事实标准,开源,一键 | NeMo(开源仓库,格式出口保留)、TRL 裸写 | GPU 到位后按体验复评 |
| 代理训练(CPU) | **transformers+peft** 手写循环 | Actions 免费 CPU 可跑;超参签名过滤保跨版本 | LLaMA-Factory(CPU 下过重) | 有 GPU 后此路退役为应急 |
| 代理模型 | **Qwen2.5-0.5B/7B-Instruct** | 中文强、许可宽松、0.5B CPU 可训 | Llama3.x(中文弱)、MiniCPM | 换评测域时复评 |
| 评测 | **自研判分**(精确匹配) | 可验证域零波动;协议入册可审计 | LLM-as-judge(波动大,违反 A1 验收) | 不可验证域产品化时另立 judge 协议 |

## 3. 上游三项目的定位(docs/01/04 结论落位)

| 项目 | 采用方式 | 不采用的部分 |
|---|---|---|
| Data-Juicer | **引擎适配器**(dj-process 子进程,选装)+ Ray 去重零件(规划)+ Sandbox 方法论 | 不把配方写进它的 YAML 体系 |
| DataFlow | **思路层**:KBC/reasoning 流水线设计、Harness 的 NL2Pipeline 模式 | 不引其运行时(单机 pandas) |
| NeMo | **格式出口**(bin-idx/SFT/messages/DPO)+ 开源仓库(Curator/RL)按需 | 闭源微服务/NIM 一概不用(红线) |

## 4. 商业与基建

| 领域 | 选择 | 理由 | 落选备选 | 重估触发 |
|---|---|---|---|---|
| 支付-国内 | **支付宝当面付**(python-alipay-sdk)主;微信(wechatpayv3)备 | 个体户可签;二维码匹配 CLI/网页形态;SDK 开源 | 官方 alipay-sdk-python(API 形态繁琐) | 微信商户号到手即双栈 |
| 支付-国际 | **Stripe 标准库直连** | 回调验签可 stdlib 实现,零 SDK | PayPal、DodoPayments(MoR,出海规模化再评) | 出海正式化 |
| 商业外壳 | **TinyShip**(gate 后购,私有仓库) | 国内双栈+Better-Auth,几百元 vs 2-4 周人力;license 禁止入开源仓 | ShipFast(无国内支付)、自建 shadcn(备选) | license 条款有意外时转自建 |
| 托管 | **Render 免费档**(测试)| 无卡免费、公开仓直连构建、API 全程可驱动 | HF Space(Docker 已转 PRO 付费,实测 402)、Koyeb(备选)、Fly(需卡) | 付费客户出现→付费档+持久盘(P0-1) |
| CI/跳板 | **GitHub Actions** | 公开仓免费;跑器有完整外网,是本环境唯一出网跳板(实证:部署/实验/验收全靠它) | — | 无 |
| 容器 | **Docker 单镜像** | Render/自托管通用 | — | 无 |
| 文档站 | **GitBook 结构**(.gitbook.yaml/SUMMARY)+ HonKit 静态备选 | Git Sync 零维护;HonKit 已验证可自托管 | Fumadocs(归外壳仓库) | 外壳上线后统一到产品站 |
| 图形产物 | Chromium headless + Pillow | 环境自带;SVG→PNG 链路已踩通(滚动条/缩放坑已记录) | ImageMagick(未装) | 无 |

## 5. 选型纪律

1. 新依赖入库前问三条:开源许可?替换成本(<2 周?)判断类还是执行类?——判断类必自研
2. 每项选型写明**重估触发条件**,触发即回本文更新,不许"顺手换"
3. 版本 pin 策略:应用依赖下限约束(>=),实验脚本按运行时签名做兼容(transformers 教训,52071d7 前的兼容修复)
