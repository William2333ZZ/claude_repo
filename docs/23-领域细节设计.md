# 23 · 领域细节设计:角色、用例、旅程与状态机(2026-08-15,委托人「用户怎么用、平台怎么设计,都是领域的细节」指令)

docs/22 定了名词(统一语言/上下文),本文定**动词与时间**:谁(角色)、做什么(用例)、
按什么顺序(旅程)、对象经历什么(状态机)。核心方法论一句话:

> **体验是领域的投影**。一个用例 = 一个领域动作,恰有三种投影(REST / CLI / MCP),
> 将来加第四种(只读控制台 #19)。三投影必须同语义、同统一语言;缺投影是登记在册的
> 缺陷,不是"以后再说"。
>
> **2026-08-15 升级(docs/26)**:投影之上加**剧本层(Skill)**——harness 装技能,
> 技能编排投影,登录是剧本第一幕。入口序与验收方式("Skill 走查")以 docs/26 为准。

## 1. 角色(Actors)

| 角色 | 是谁 | 入口 | 权限要点 |
|---|---|---|---|
| 访客 | 好奇的实干者 | landing + `datafoundry demo`(本地零依赖) | 无账户,不触云 |
| **实干者** | 半懂的付费者(docs/14 §11.2 唯一画像) | CLI(本地)/ REST(云) | 只见自己的数据集/run/账户 |
| **智能体** | 替实干者干活的 Claude Code / dsh / Codex | MCP(持其人类的 API key) | **与其人类同权,不多一分**——agent 无特权是 I5 的权限面表述 |
| 管理员 | 运营者(现=委托人) | REST 管理端点 + CLI create-user | 用户/授信/审计读取 |
| Mission | 智能体的定时形态 | MCP + 事实文件 | 只读事实 + 拟提案;**只花人预授预算、超即停、永不自我扩权**(预算制授权,docs/24 Q6) |

## 2. 核心旅程(用例串 + 每步落下的领域事件)

**旅程 A · 首次价值(访客 → 付费实干者)**
```
demo(本地,免费无限)→ 注册/login → upload 数据集 → estimate(免费,先算账)
→ 充值(Order: pending→paid→credited)→ run(扣费)→ 读尸检(死因分布+样例)
→ 下载幸存集 + 交差报告
```
事件:`OrderPaid` → `RunCompleted` → `SampleKilled`×N。转化关键位:**estimate 免费**
(看见"能省多少钱/杀掉什么"才愿付费)与**尸检可读**(付费后的"值了"时刻)。

**旅程 B · 复购(证据驱动)**
```
recipes + history(配方档案:上次留存/成本/评分)→ estimate → run → eval 写回
```
事件:`EvalScored` 附着回 run → 配方档案变厚 → 下次选型更准(飞轮左轨)。

**旅程 C · 托管(Mission,R4)**
```
订阅事实文件 → 发现异常(留存骤降/死因偏移)→ 拟配方修正提案 → 人授权 → run
```
Mission 只产提案,授权永远在人——主链四段(docs/21 §0)的运营形态。

## 3. 生命周期状态机(聚合的时间维度;非法迁移=组装错误,响亮失败)

| 聚合 | 状态机 | 设计裁定 |
|---|---|---|
| **Run** | queued → running → completed \| failed | "授权"现阶段 = 余额扣款成功(最小实现,写为正典);显式 authorized 前置态留给企业预算制(触发:首个企业单) |
| **Order** | pending → paid → credited(webhook 幂等,同事务) | 改进项:pending 超时 expired(现无过期,陈单永挂)→ #28 |
| **Recipe** | published(hash 即版本)→ superseded | **无 draft 态**:配方即代码,草稿流程 = PR 流程,不另建 |
| **Dataset** | registered/uploaded → 被 run 引用 | 删除权设计:数据集**内容**可删,事实记录(manifest 引用 + sha256)永存——内容不可复原即满足删除权,审计链不断(I1 与合规的平衡) |
| **ApiKey** | active → revoked | 已实现 |

## 4. 用例 × 三投影矩阵(2026-08-15 实测现状,诚实缺口)

| 用例 | REST | CLI | MCP | 裁定 |
|---|---|---|---|---|
| 估算(先算账) | ✅ /pipelines/estimate | ✅ refine 内嵌(本地) | ✅ df_estimate_pipeline | 齐 |
| 执行精炼 | ✅ /runs | ✅ refine(本地版) | ✅ df_run_pipeline | 齐(CLI 是离线投影,有意) |
| **读尸检/死因** | ✅ /runs/{id}/rejects | ❌(audit 只吃本地目录) | ❌ | **#28 首位:df_get_rejects——死因是产品核心语言,智能体居然还读不到云端死因** |
| 评测写回 | ✅ /runs/{id}/eval | ❌ | ❌ | #28 次位(旅程 B 的 MCP 闭环) |
| 配方与档案 | ✅ /recipes+history | ✅ recipes --history | ✅ df_recipe_history | 齐 |
| 上传数据集 | ✅ | ❌(本地流不需要) | ✅ df_upload_dataset | 齐(CLI 缺口有意) |
| 账务自查/建单 | ✅ /billing/me | ❌ | 🔶 df_create_order(#29-D) | 裁定精确化(docs/26 §3-D):**支付授权不进 MCP,建单与查余额可进**——建单是拟提案,扫码支付才是授权 |
| 用户/授信管理 | ✅ | ✅ create-user | ❌ | **裁定:管理面永不进 MCP**(安全线的权限面延伸) |
| 合规证据包 | ❌(本地工具) | ✅ audit | ❌ | 云端化随 #20 交付打包统一 |

矩阵纪律:新用例必须三投影同批落地,或在此登记缺口与理由;"❌ 且无裁定"不允许存在。

## 5. 平台设计细节(把体验规则写成正典)

1. **估算先行**:estimate 永远免费;run 的 manifest 必录 est_cost_total(已实现),
   实际成本偏离估算 >50% 记异常事件(改进项,#28)。
2. **死因首屏**:#19 控制台首屏 = SampleKilled 投影(死因分布 + 可复核样例),
   控制台是**第四投影,只读**——绝不长出独立写路径。
3. **错误即导购**:失败必须用统一语言并指路(组装错误已达标:缺依赖报"请先加入
   quality_score";改进项:余额不足应报"差 ¥X,充值入口在 Y")。
4. **幂等**:订单已幂等;run 创建加 client_token 防双击重跑(#28)。
5. **agent 与人同权**:MCP 面不出现任何管理/支付动作;智能体能做的,它的人类都能做;
   反之不成立(管理面、支付面人类专属)。

## 6. 私有仓与开放面(委托人 2026-08-15 决定:产品仓转私有)

代码转私有后,"任何人可复现"的对外叙事调整为**私有产品仓 + 公开证据橱窗**:
战役报告(autopsy.json/AUTOPSY.md/复现说明)迁入未来公开 showcase 仓;完整复现
待 datafoundry-core 上 PyPI 后恢复("pip install + 公开尸检脚本"路径)。对外素材
纪律(seed+sha+可复核样例)不变,变的只是代码可见性。

## 7. 纪律

- 新用例:三投影同批或矩阵登记;新状态迁移:必有领域事件 + 测试
- 管理面永不进 MCP;**支付授权**永不进 MCP(建单/查余额可进,docs/26);Mission 只花人预授预算(docs/24 Q6),永不自我扩权
