## 1. 产品架构:卖什么、给谁、怎么流转

一句话:**开源建信任 → 报告证效果 → 自助成交 → PoC → 大单**;凡"判断类核心资产"只进付费层。

```mermaid
flowchart LR
    P2["P2 微调者·应用公司<br/>自助,零销售"] --> T1
    P1["P1 垂直模型团队<br/>设计锚点,付费意愿最强"] --> T1
    subgraph T1["① 信任层(免费)"]
        K["开源内核 Apache-2.0 ✅"]
        H["Claude Code harness<br/>MCP 9 工具 ✅"]
        R["C2 公开报告 🟡<br/>四种子已档"]
    end
    T1 --> T2["② 试驾<br/>demo·五分钟指南·设备码登录 ✅"]
    T2 --> T3["③ 自助成交<br/>配方包 🟡 math 雏形<br/>额度包 ¥99/¥499 ✅代码级"]
    T3 --> T4["④ PoC ¥9,900<br/>断点:支付宝提审 + P0-1"]
    T4 --> T5["⑤ 年费订阅 20-40万 ⚪<br/>垂直交付 文档→模型 ⚪ gate后"]
    SHELL["商业外壳 TinyShip·Next.js ⚪ gate后<br/>官网·微信登录·收银台"] -.->|承载 ③④⑤| T3
```

| 产品形态 | 状态 | 商业角色 |
|---|---|---|
| 开源内核 / harness | ✅ 可用(57 例测试) | 不卖,获客漏斗顶部 |
| 公开报告(C2) | 🟡 四种子数据齐,LLM 组并入中 | 营销资产,可复现=可信 |
| 托管实例(Render) | 🟡 测试级 | 自助订阅载体,P0-1 后承接付费 |
| 配方包(买断) | 🟡 首个雏形 = math_zh_funnel_v1 | 类 boilerplate 售卖 |
| 额度包/PoC 包 | ✅ 代码级(下单→扫码→核账→扣减全链) | 自助/首单成交物 |
| 合规证据包 | ✅ `datafoundry audit` | 差异化卖点(监管刚需) |
| 商业外壳 | ⚪ gate 后购建 | 渠道,不是商品 |

```mermaid
    DB[("存储 SQLite v0<br/>→ PostgreSQL(P0-1)⚪")]
    LLM["LLM 后端 · OpenAI 兼容协议<br/>DeepSeek ✅ 在用"]
    DJ["Data-Juicer 引擎适配<br/>子进程,选装"]
    SHELL2["商业外壳 Next.js ⚪<br/>四区制:Auth/Public/Protected/Admin"]

    CLI --> API
    MCP --> API
    WEB --> API
    API --> AUTH --> REC
    OPS --> REC
    REC --> FUN --> RUN --> AUD
    API --> BILL
    AUTH --> DB
    BILL --> DB
    RUN --> DB
    RUN -.->|judge·QA 合成| LLM
    RUN -.->|可选引擎| DJ
    SHELL2 -.->|API Key 签发·额度同步| API
```

**权限即架构**:Agent(MCP)与人(CLI/Web)走同一 API、同一鉴权——Agent 能力严格等于其
API Key 对应角色;收银台在外壳、**账本在内核**(docs/11 边界)。
