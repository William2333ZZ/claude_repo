# 22 · 领域模型与统一语言(2026-08-15,委托人「采用领域驱动设计,与 harness 设计哲学一致」指令)

本文是 DDD 维度的正典:统一语言、限界上下文、聚合↔不变量↔守护、领域事件。
技术分层(kernel/service/interface)见 docs/21 §7,两个维度正交,均由
tests/test_domains.py 守护。**词汇即产品**:对"半懂的实干者"(docs/14 §11.2),
说人话的术语表就是第一层用户界面。

## 1. 统一语言正典(Ubiquitous Language)

| 术语 | 代码名 | 一句话定义 |
|---|---|---|
| 样本 | `schema.coerce_sample` | id/text/meta/stats/trace 的最小事实单元;id 是引用,**血缘(parent_id 链)才是身份**(docs/24 Q1) |
| 算子 | `registry.Op` | 对样本的单一处置;声明成本档、留存先验、依赖契约 |
| 死因 | trace kill detail | 样本被杀的**可辩护理由**,append-only;**只由确定性算子/已授权阈值签发**,判审理由是证词不是死因(docs/24 Q2) |
| 漏斗 | `funnel_compile` | 按成本档、保依赖的稳定重排:便宜的先杀,贵的只看幸存者 |
| 配方 | `recipes` + recipe_hash | 可授权、可回滚、可归因的处置策略版本(hash 即身份) |
| 运行 | Run / `manifest.json` | 一次精炼的完整事实记录 |
| 判审 | judge(`stats.judge_score`) | AI 建议,**永不单独杀样本** |
| 质量分 | `stats.quality` | 启发式**代理指标**;质量的裁决权在评测分——对外禁裸称"质量分"(docs/24 Q4) |
| 裁决 | 验证器/已授权阈值 | 确定性的处置权(同输入+同配方→同输出) |
| 铁证 | `stats.false_equation` | 复算必错、惯例已豁免的死刑(v3 尸检语义) |
| 惯例记账 | convention stats | 数学不严格但非算错的书写,记账放行不判死 |
| 依赖契约 | `requires_stats`/`provides_stats` | 算子对上游的需求与自身供给,组装期校验 |
| 证据包 | `audit` | 监管口径的事实组装(manifest/rejects/output → 报告) |
| 账本 | ledger | append-only 资金事实;余额 = SUM(ledger) |
| 窄腰 | docs/21 律二 | 四条稳定接口:样本 schema / 算子协议 / 事实文件族 / MCP 工具面 |
| Mission | 计划/事件触发的智能体会话 | 托管运营形态,不自建工作流引擎 |

纪律:新概念先入此表再入代码;代码名与术语不一致视为缺陷。

## 2. 限界上下文与上下文映射

> v0.2 拆包后模块路径为 `datafoundry.<域>.<模块>`(kernel/service/interface,docs/21 §7);
> 下表模块名不变;顶层无任何代码文件(shim 兼容期已结束,唯一路径即正典路径)。

| 上下文 | 模块 | 聚合根 | 对外语言 |
|---|---|---|---|
| **精炼**(核心域) | schema/registry/pipeline/runner/ops/engines/matheq | **Run** | 事实文件族 |
| **配方**(第二核心) | recipes | **Recipe**(hash 即身份) | recipes API / df_recipes |
| **证据与合规** | audit | EvidencePack | 审计报告 |
| **账务**(通用子域) | billing(+store 的 orders/ledger 表) | **Order→Ledger** | 支付回调 / 余额 |
| **身份与门禁**(通用子域) | security/ratelimit | User/ApiKey | 登录 / RBAC / 限流 |
| **接入** | cli/mcp_server/credentials | (无状态客户端) | HTTP 窄腰 |
| **组装与存储** | server/store | (组合根+持久化) | REST |

**映射关系**:精炼是核心域,配方与证据是护城河所在;账务/门禁是通用子域,能租则租、
保持薄。下游(证据/评测/档案/agent)**只读事实文件,永不反向调用**上游。

**防腐层(ACL)四处**——外部世界的变化挡在接口后,这四处正是 dsh 所谓 capability seam
(Definition/Provider/Consumer 三角)的我们版本:
1. **引擎座**:Data-Juicer 经 subprocess(进程边界即最硬防腐层),`engine=datajuicer` 可换
2. **支付**:AlipayProvider 接口(page/precreate 是配置;Stripe/微信同座)
3. **存储**:`_sql`/`_txn` 方言漏斗(SQLite/PostgreSQL 双后端,P0-1 零业务改动实证)
4. **认知**:BYOK 环境变量端点 + REST 窄腰(技能剧本直驱,MCP 为可选适配器;模型与 harness 皆可插拔,I5)

## 3. 聚合 ↔ 不变量 ↔ 守护(不变量必须有主人,主人必须有卫兵)

| 聚合根 | 拥有的不变量 | 守护测试 |
|---|---|---|
| Run | I1 处置必有死因(trace append-only)· I4 可复现(manifest 全录) | test_runner / test_streaming |
| Recipe | 所见即所签:hash 即授权对象(I2 的授权半边) | test_recipe_archive |
| Ledger | I3 资金唯一写入点、同事务、幂等 | test_store(支付幂等) |
| 算子链 | 依赖显式:requires/provides_stats,缺即拒编译 | **test_stat_deps(本轮新增)** |
| 域边界 | 内核零第三方、分层单向、上下文全划分 | test_domains |

## 4. 领域事件目录(事实=事件;Mission 的订阅点)

| 事件 | 当前载体 | 订阅者(现在/将来) |
|---|---|---|
| SampleKilled(死因) | rejects.jsonl 行 | 尸检报告 / 回收再利用 |
| RunCompleted | manifest.json | 评测 / 配方档案 / Mission |
| JudgeLabeled | judge_labels.jsonl 行 | 蒸馏管线(租的认知→自有资产) |
| OrderPaid | ledger 行(webhook 幂等落账) | 权益发放 / 对账 |
| EvalScored | eval 写回 run | 配方归因 |

原则:**事件是已发生的事实**,载体一律 append-only;事件名进入统一语言;
Mission 订阅的是事实流,不是过程内部。今天载体是文件与行,将来若上事件总线,
换的是载体不是语义(窄腰③不动)。

## 5. 与 dsh 设计哲学的对齐与分歧

| dsh | DataFoundry |
|---|---|
| Everything is a plugin,无特权核心 | 一切处置皆算子,runner 无特权逻辑,引擎可换 |
| "Model-visible means logged"(运行时断言) | 处置可见必有 trace;对外可见必可复现(I1/I4) |
| Capability seam 三角 | 四大防腐层(§2) |
| 缺服务 = 组装错误,加载即响亮失败 | **缺依赖 = 拒编译**(stat_flow_errors,本轮落地) |
| durable fact vs live extension point | 事实文件族 vs API/MCP 调用 |
| session log 唯一真相源 + 投影(deriveMessages) | 事实文件+账本唯一真相源;死因分布/余额=纯函数投影 |
| **分歧(有意)**:管长驻会话的动态组合 | 管批处理事实的确定裁决——运行时不自建(docs/21 §4) |

## 6. 纪律

- 新术语必先入 §1;新模块必入 test_domains 两个维度(技术层 + 限界上下文),测试逼问归属
- 新算子凡有跨算子协作,必声明 requires/provides_stats——沉默的约定视为缺陷
- 新事件载体必 append-only;投影必是纯函数
- 本文档与 docs/21 冲突时,以后修订者负责消解并留痕
