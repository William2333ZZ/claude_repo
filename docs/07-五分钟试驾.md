# 07 · 五分钟试驾指南

> **2026-08-15 起最快路径**:把仓库 `skills/` 四个目录拷进 `~/.agents/skills/`,对你的 harness(Claude Code/dsh)说"帮我清洗一批数据"——注册、登录、估算、尸检全由技能剧本引导(docs/26)。本文的 CLI/API/MCP 路径仍然有效,适合手动逐步体验。


> 在你自己的机器上实测平台与设备授权登录流。以下命令已在干净克隆 + 独立 venv 里完整验证过
> (Python ≥3.10 即可,无 GPU 要求)。

```bash

```

## 第 1 步:起服务并建账号(1 分钟)

**终端 A**(保持开着):

```bash
datafoundry serve                     # 默认 127.0.0.1:8321
```

**终端 B**:

```bash
# 创建第一个 admin(二选一):
datafoundry create-user --username alice --role admin   # 交互输入口令(≥8 位)
# 或: curl -X POST localhost:8321/auth/bootstrap -H 'Content-Type: application/json' \
#        -d '{"username":"alice","password":"你的口令"}'
```

## 第 2 步:测设备授权登录(2 分钟,重点)

```bash
datafoundry login
```

你会看到(同 feishu-cli 的体验):

```
在任意设备的浏览器打开并完成授权:
  http://127.0.0.1:8321/device?code=XXXX-XXXX
  授权码: XXXX-XXXX(页面已预填,核对即可)
等待授权中...(Ctrl-C 取消)
```

浏览器会自动弹出(SSH 场景手动打开链接,**手机开也行**,只要能访问到这台机器)。
页面上输入 alice 的用户名口令,点「授权」→ 回到终端,几秒内应显示:

```
已登录 alice(admin),凭据保存至 ~/.datafoundry/credentials.json
```

验证与登出:

```bash
datafoundry whoami        # {"id": 1, "username": "alice", "role": "admin"}
cat ~/.datafoundry/credentials.json   # 权限应为 -rw-------(0600)
# datafoundry logout      # 最后再测:吊销服务端 Key + 清本地凭据
```

可选加测:
- **两段式(Agent 模式)**:`datafoundry login --no-wait --json` 拿 device_code,
  浏览器授权后 `datafoundry login --device-code dfd_xxx --json` 续轮询
- **拒绝路径**:发起登录后在页面点「拒绝」,终端应报 `登录失败: denied`
- **口令直连**:`datafoundry login --password`(不走浏览器)

## 第 3 步:跑一条真实流水线(1 分钟)

登录态下直接用 API(凭据文件已生效,也可以走 MCP,见第 4 步):

```bash
KEY=$(python3 -c "import json,pathlib;print(json.loads((pathlib.Path.home()/'.datafoundry/credentials.json').read_text())['api_key'])")

# 传三条样本(两条重复、一条太短)
printf '%s\n' \
 '{"text":"这是一条足够长的正常样本,用来验证端到端流水线。这是一条足够长的正常样本。"}' \
 '{"text":"这是一条足够长的正常样本,用来验证端到端流水线。这是一条足够长的正常样本。"}' \
 '{"text":"太短"}' \
| curl -s -X POST 'localhost:8321/datasets/upload?name=trial' -H "X-API-Key: $KEY" \
       -H 'Content-Type: text/plain' --data-binary @-
# 记下返回的 "id"(ds_xxx),然后:
curl -s -X POST localhost:8321/runs -H "X-API-Key: $KEY" -H 'Content-Type: application/json' \
  -d '{"dataset_id":"ds_xxx","steps":[{"op":"length_filter","params":{"min_len":10}},{"op":"exact_dedup"}]}'
# 用返回的 run_xxx 查结果(期望 n_in:3, n_out:1, rejects 带死因):
curl -s localhost:8321/runs/run_xxx -H "X-API-Key: $KEY"
```

## 常见问题

| 现象 | 处理 |
|---|---|
| `无法连接 127.0.0.1:8321` | 终端 A 的 serve 没起,或端口被占(`datafoundry serve --port 8399` 换端口,login 加 `--url`) |
| 浏览器没自动弹出 | 正常(SSH/无图形环境),手动打开打印的链接即可,手机开也行 |
| 授权页提示口令错误 | 口令≥8 位;用户名只允许字母/数字/下划线 |
| 登录超时 | 授权码 10 分钟过期,重新 `datafoundry login` |
| `slow_down` 事件 | 正常,轮询限速在工作,CLI 会自动加大间隔 |

测完把结论(尤其是别扭的交互)记下来——登录体验的毛刺就是下一轮要打磨的需求清单。
