# 28 · 看板平台:toC 的"看的面"(2026-08-15,委托人「平台是一个 toC 的那种看板平台」指令)

委托人两点(逐字):**① 平台的架构需要设计一下;② 平台是一个 toC 的那种看板平台。**

## 0. 领会:两面论——操作台是用户的 harness,看板台是我们的网页

Skill 优先公理(docs/26)不动:**"做"的面**在用户的 harness 里(技能剧本直驱 REST)。
本文补上此前被压缩掉的另一半:**"看"的面**——普通付费者(toC,半懂的实干者,
docs/14 §11.2)打开网站应当看到一个**看板产品**:我的运行、死因人话、余额流水、
淘汰了多少垃圾、配方战绩。看板负责**看见、信任、批准、付钱、转发**,
永不与技能抢"做"的活。

docs/26 §0 的"网页收缩为两样"(设备码授权页 + 只读证据页)由此**升格**:两样收编进
看板平台,加上账户区与公开橱窗,成为产品脸面。公理①②(harness 装技能、技能带登录)
一字不动——看板是技能干完活之后,**人来看账的地方**。

## 1. 架构不变量:看板是投影,不是第二个大脑

1. **一切页面 = 事实的纯投影**:死因分布投影自 rejects.jsonl,余额 = SUM(ledger),
   配方战绩投影自 manifest 族——看板不产生新事实,只呈现已裁决的事实(I1/I4 的展示面)。
2. **写动作白名单制**(§3):白名单全部是"人手环节";白名单外绝不长出独立写路径,
   入口与 REST 共用同一 service 函数,禁止第二套业务逻辑。
3. **看板可整体宕机而平台照常干活**:技能/REST/kernel 对看板零依赖——看板是脸,不是心脏。
4. 窄腰四条不动。看板 = **第四投影转正**(逐页清单见 §2;不并入 docs/23 §4 矩阵加列,
   防双表漂移——矩阵管"用例×投影",本文管"页×投影自")。

## 3. 写动作白名单(每一条都是"人手环节",与安全线同构)

**准入**:注册/登录(密码人打、TLS 直达服务端,**永不经 agent**,与设备码流互补)·
**harness 免密直登**(委托人同日指令「网站应能用 dsh 打开,用存下来的 key」:技能持存盘
key `POST /auth/web-login` 换 120 秒**一次性令牌**,浏览器点开换会话 cookie 入看板——
设备码流的镜像;**裸 key 永不进 URL**,进 URL 的只有单次消费令牌)·
设备码批准 · 建单 + 去支付(**支付授权永远人手**,看板正是人手所在)· 下载交付 ·
分享链生成/吊销 · API key 吊销 · 样例尸检(服务端自带样本、零扣费、限流)。

**明确不进 v1**(登记触发,不是遗漏):浏览器上传/配管线/跑管线——"做"的活留给技能面;
触发 = 看板访客中无-harness 用户占比可观(服务端日志计数),届时按"向导"形态另行设计。
REST 窄腰天然支持(网页只是又一个客户端),加它不需要重构,所以更不必抢建。

## 4. 选型(与 docs/27 反浪费五原则同构)

> **2026-08-15 委托人裁定(晚于本文初版)**:看板前端 = **Next.js 外壳**,并入通用脚手架
> (docs/29 §3.5)。此裁定与 docs/13「外壳框架 = Next.js」ADR 合流;本文初版的
> "Jinja2 零构建链"改判为**内核兜底页纪律**(落地页/设备码页/最小证据页保持零框架),
> 真 UI 归外壳。下表按裁定后口径。

| 项 | 选型 | 为什么 | 重估触发 |
|---|---|---|---|
| 渲染 | **Next.js 外壳**(独立包/独立部署物,BFF 只吃 REST 窄腰);内核兜底页保持无框架 SSR | 真 UI 归外壳(docs/13 ADR:shadcn 一等公民 / AI 执行单元在 React/Next 质量最高 / 招聘池);内核零 node 依赖 | 团队以 Vue 为主 → 复评 Nuxt |
| 交互 | 外壳组件体系(shadcn/ui 系);内核兜底页零框架零外链 | 组件一等公民,AI 生成质量高 | TanStack Start 逃生门(组件层共享) |
| 会话 | 会话 cookie **归外壳域**——外壳 `/df/*` 同域反代到 API,Set-Cookie 与相对 303 自然落在外壳域,**既有 /auth/web 令牌端点零改动复用**;**POST 全 CSRF** | toC 不可用 HTTP Basic;裸 key/令牌纪律不变;同一后端兼容直连与代理两种入口 | — |
| 样式 | 外壳自带体系 + 暗/亮双主题 + CJK 字体栈 | **手机是 toC 第一屏** | — |
| 图表 | 服务端算好数字 + CSS 条(死因分布现法) | 零图表库;数字先于图形 | 需要趋势/分布图时再议 |
| 邮箱 | v1 无邮件设施(注册可留邮箱字段;找回 = 管理员重置) | 邮件服务商是新外部依赖,届时挂 ACL 再接 | 找回诉求真实出现 |
| 埋点 | 服务端日志计数(页/转化位),无第三方脚本 | 隐私 + 零依赖 | 需要漏斗分析时再议 |

## 5. 域归属与守卫

- 新限界上下文**「呈现」**(2026-08-15 晚裁后形态):**看板外壳 = 顶层 `web/` 独立包**
  (Next.js,自有部署物,永不进 python 包);console.py 降级为内核**兜底证据页**留在
  service(GLOSS 人话与死因首屏语义迁入外壳时保持同词);docs/22 §2 表随 30-A 同步。
- 外壳只吃 REST 窄腰(BFF)——**外壳侧没有进程内读**,写与读同走窄腰;内核兜底页
  维持进程内只读投影。守卫:python 包内禁出现 node 资产;外壳仓禁直连数据库。
- test_domains 随 30-A 增补呈现上下文守卫(python 包内禁 node 资产);内核零依赖不变。

## 6. 验收:看板走查(与 Skill 走查成对)

拿一台手机,从 Landing 走到底:样例尸检 → 注册 → (换 harness 用技能干活)→
回看板读死因 → 充值到账 → 下载交付 → 生成分享链发给"老板"。
走不通的一步 = 平台缺陷。走查记录入 gate 报告(docs/20 形态),与 Skill 走查并列两栏。
